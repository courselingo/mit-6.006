第一讲讲的是怎么把一个问题解开，这一讲先停下来问一个更靠前的问题：说一个算法「快」，到底是在给什么定价。不先约定「哪种操作算一步、一步要多久」，复杂度分析就只是一句口号。而一旦把「写法」的自由算进去，同一台机器上的差距可以很大：本讲最后那张表的八行全在同一台机器、同一个 CPython 2.6.2 上跑，只改 Python 代码，就从 228.1 秒掉到 0.2 秒。

MIT 6.006 的第二讲就叫 [[term:model-of-computation]]，副标题是「计算模型、Python 的代价模型、文档距离」这三件事；讲义开头的 Lecture Overview 列的是五条：什么算算法与什么算时间、[[term:random-access-machine]]（random access machine）、[[term:pointer-machine]]（pointer machine）、Python 模型、以及 [[term:document-distance]]（document distance）。这一讲的推进顺序值得先记住：先定机器，再把 Python 的写法映到机器上，最后拿「两篇文档有多像」把代价算个明白。

## 一、这一讲要解决什么：算法是什么，代价又是什么

讲义用一段历史开场。花拉子米（Al-Khwārizmī，约 780 到 850 年）被称作代数之父，他那本《复原与对消的计算概要》里解线性与二次方程的办法，被讲义点名为「最早的算法之一」。顺带说一句讲义里没有写的事：algorithm 这个词本身就是他名字的拉丁化（经中世纪拉丁语 algorismus）。

接着讲义给了算法的两个说法：它是「计算机程序的数学抽象」，也是「解决问题的计算过程」。抽象这两个字是重点。同一件事，写成程序要落到某台具体的机器上，写成 [[term:pseudocode]] 只需要落到一套规则上。讲义那张图是两列三行：左列自上而下是 program、programming language、computer，右列自上而下是 algorithm、pseudocode、model of computation；两个图例是 analog（类比）与 built on top of（建立在……之上），前者在正上方，后者在最右侧。标签之间怎么连，讲义的文字部分没有说明，我们的核对也读不到箭头，所以这里只复述标签的位置，不替它推断连线。

> 原文：Model of computation specifies what operations an algorithm is allowed; cost (time, space, …) of each operation. Cost of algorithm = sum of operation costs.

译过来是：计算模型规定了算法允许做哪些操作，以及每个操作花多少代价；而一个算法的代价，就是它用到的所有操作代价之和。这句话是这一讲的骨架，后面 RAM、指针机、Python 模型都是它的具体版本。这门课的教材 CLRS 里，绝大多数算法就是在这个模型下分析的。

![程序与算法并列在上、计算模型在下：计算模型规定允许哪些操作、每个操作多少代价](figures/model-of-computation.svg)

## 二、随机存取机：把一次操作定价为 Θ(1)

第一个模型叫随机存取机，缩写 RAM。它把内存想成一个很大的数组，每个格子有 [[term:index]]，格子里的东西叫 [[term:machine-word]]。除了内存，机器还有常数个寄存器，每个也是一字大小。讲义列的允许操作只有三条，而且都在 Θ(1) 时间里完成：

- 把某个内存地址的字装进一个寄存器；
- 在寄存器上做加减乘除与按位运算；
- 把一个寄存器里的字存回某个内存地址。

三条之外就没有了。这个「只有三条」的设计，正是它能给复杂度分析当尺子的原因：任何算法只要拆成这三条，代价就能对着数出来。

这里有个容易被跳过但很关键的细节：一个字到底是多少位。讲义写的是 \(w \ge \lg(\text{memory size})\) bits。意思是字长必须够放下一个内存地址，否则你连「指到某个格子」都做不到。同时约定基本对象（比如一个整数）能塞进一个字，所以两个整数相加算一次操作。到了第四单元讲大数运算时，这个约定会被拆掉重新讨论。

![随机存取机：大数组当内存，常数个寄存器，三条 Θ(1) 操作](figures/ram-model.svg)

## 三、指针机：只有对象和引用

第二个模型叫 [[term:pointer-machine]]。它不假设内存是一个大数组，而是假设动态分配出来的对象：每个对象有常数个字段，每个字段要么是一个字（比如一个整数），要么是一个指向别的对象的引用，要么是空。Python 里的 `namedtuple` 就是这个东西。

两种模型的关系，讲义只用了一句括注说清：指针机比 RAM 弱，因为它可以在 RAM 上实现出来。换句话说，它能做的 RAM 都能做，反过来不成立：RAM 能表达的东西更多。少在哪里？它没有「第 i 个格子」这种随机寻址，只能顺着引用走。这一点在后面讲链表时会长出代价：链表上就没有「一步跳到中间」。

既然更弱，为什么还要留着它？因为**描述这类结构时它更顺手**：链表、树、图的邻接表本来就是「对象加引用」，用指针机的眼光写出来，代码与推理都更贴近人话；要真跑起来，再把它翻译到 RAM 上就行。（这一句是讲义没有写、我们补的理由。）

![指针机：动态对象、常数个字段，字段是字或引用](figures/pointer-machine.svg)

## 四、Python 的代价模型：把一行代码映回机器

先把这一讲的数量理清：计算模型有**两个**（RAM 与指针机），Python 的代价模型是**第三个东西**，而且它不是一个新机器 —— 它是一张对照表，说明「Python 的每一种写法各自落到上面哪个模型上」。所以下面这一段讲的不是第三个模型，而是 Python 怎么在这两个模型之间来回。

Python 的好处，也是它的坑，在于它同时提供上面两个模型的写法：

1. `list` 实际上是一个数组，所以 `L[i] = L[j] + 5` 是 RAM 式的随机寻址，花 Θ(1)；
2. 带常数个属性的对象是指针机式的，所以 `x = x.next` 顺着引用走一步，也花 Θ(1)。

于是判断 Python 某个操作贵不贵的办法就定了：想象它按上面两个模型实现出来要几步。

讲义把常用的几个列了出来，这份清单值得背下来，因为它决定了后面每一讲里「一行 Python 算几次操作」。下面只展开最常用的五项；讲义另外还列了 `len(L)` 与 `L.sort()`，以及 tuple/str、dict、set、heapq、long 这几类的模型。第五条那一个圆点里含 `x in L`、`L.index`、`L.find` 三种写法，讲的是同一件事：

- `L.append(x)`：Θ(1)。前提是动态数组在背后按需扩容，多余的一次扩容代价被摊掉，这套账在第九讲的表倍增里算；
- `L = L1 + L2`：Θ(1 + |L1| + |L2|)。它新建一个列表，把两边逐个搬过去，长度加进去是躲不掉的；
- `L1.extend(L2)`（等价于 `L1 += L2`）：Θ(1 + |L2|)。只搬右边，左边原地留下；
- `L2 = L1[i:j]`：Θ(j − i + 1)。切片要复制出一段新列表，所以它是 O(|L|) 而不是 Θ(1)；
- `x in L`、`L.index(x)`、`L.find(x)`：Θ(|L|)。它们从头逐个比，没有下标可以直接跳。

注意最后两条的共同点：它们看起来像一次查询，实际是一整轮扫描。初学者写出来的慢代码，多半就慢在这里。

![Python 的两种模式：list 是数组（RAM），带属性的对象是指针机](figures/python-cost-model.svg)

## 五、文档距离：把「像不像」变成几何

接下来是这一讲的重头戏：给两篇文档算一个「有多像」的数。讲义用最短的例子开场：\(D_1\) 是「the cat」，\(D_2\) 是「the dog」。

定义从这一步开始：把文档看成 [[term:document-vector]]。每个出现过的词是一维，坐标就是这个词在这篇文档里出现的次数。于是文档距离最自然的定义是两个向量的 [[term:dot-product]]：

\[ d'(D_1, D_2) = D_1 \cdot D_2 = \sum_W D_1[W] \cdot D_2[W] \]

这个定义立刻出问题，讲义的原话是：

> 原文：The problem is that this is not scale invariant.

也就是说它不满足 [[term:scale-invariant]]：一篇长文档只要和另一篇有 99% 的词相同，点积出来的数仍然很大；而两篇短文档哪怕只有 10% 的词相同，数也可能更小。而这里的 \(d'\) 是距离，数大就代表远，于是结果成了「重合得越多反而显得越远」：长文档带着 99% 的重合，却比只有 10% 重合的短文档显得更远。

修法是把两个向量的长度除掉，得到归一化的点积：

\[ d''(D_1, D_2) = \frac{D_1 \cdot D_2}{\lVert D_1 \rVert \cdot \lVert D_2 \rVert} \]

其中 \(\lVert D_i \rVert\) 是第 i 篇向量的长度，也就是它的词数。这里用双竖线的范数记号，是为了和第六节里表示**字符数**的 |doc| 区分开：同一个竖线在两处指的不是同一件事。这个式子的几何含义是余弦：再取一次反余弦，量出来就是两个向量之间的夹角。

\[ d(D_1, D_2) = \arccos\big(d''(D_1, D_2)\big) \]

夹角为 0 度说明两篇文档完全相同，90 度说明它们没有共同词。讲义注明这套做法出自 Salton、Wong、Yang 1975 年的工作。

![把两篇文档变成词向量，再用夹角表示距离：0 度全同，90 度无共同词](figures/document-distance-vectors.svg)

## 六、三步算法的代价：拆词、计数、点积

讲义的算法只有三步，难点全在每步的代价：

1. 拆词：把每篇文档切成词的列表。讲义顺手给了一个警告，正则 `re.findall(r"\w+", doc)` 在一般情况下可能是指数级的，所以它给了一个逐字符的写法做对照：扫一遍文档，遇到非字母数字就收一个词，代价 Θ(|doc|)。
2. 计数：把词列表变成「词到次数」的映射。讲义给了两条路。一条是先排序再线性扫一遍合并同类项，代价 O(|doc| log |doc|)（排序的对象是全部词；讲义写成 O(k log k · |word|)，其中 k 是词数，两者同阶）；另一条是直接用 [[term:dictionary]] 边扫边加，代价 O(|doc|)，但讲义加了个 w.h.p.（高概率）的限定语。
3. 点积：把两篇的计数字典乘起来。两篇各自的不同词数记作 u₁ 与 u₂。最直接的双重循环是 O(u₁ · u₂)；如果两份计数表都按词排好序，就可以像归并那样各走一遍指针，降到 O(u₁ + u₂)。

这三步用到三个量，本篇给它们三套记号，不混用：|doc| 一律指文档的**字符数**，u 一律指**不同**词数，k 只在转述讲义原式时出现，指切出来的词（token）个数。另外提一句：第五节归一化点积里的双竖线 \(\lVert D \rVert\) 是向量的长度（也就是词数），与这里的 |doc| 不是一回事，两处记号特意分开写。

第二步那个 w.h.p. 值得单独说一句，因为它很容易被读成另一件事。w.h.p. 说的是「高概率成立」；至于「字典的查找与插入是期望意义下 Θ(1)」这半句是我们的补充，讲义两处都只写了概率式（`θ(1) time w.h.p.` 与 `O(|doc|) w.h.p.`），没有给期望界。两者不能互相代替：期望是平均值，高概率是几乎必然，而且它们都不保证最坏情况。最坏情况会退化，原因与哈希冲突有关，那是第三单元要专门处理的事。所以这一讲给出的不是最终答案，而是把「哪一步值得优化」指了出来。

![文档距离的三步与各自代价：拆词、计数（排序法或字典法）、点积（双重循环或归并）](figures/docdist-steps.svg)

## 七、从 228 秒到 0.2 秒：八个版本的实测

讲义最后给了一份实测记录，这也是这一讲最值得记住的地方。测试对象是两篇文本：一篇 268,778 字符、49,785 词、3,354 个不同的词；另一篇 1,031,470 字符、182,355 词、8,534 个不同的词。机器是 2.8 GHz 的 Pentium 4，CPython 2.6.2，Linux 2.6.26。

| 版本 | 耗时（秒） | 这一步改了什么 |
| --- | --- | --- |
| docdist1 | 228.1 | 三步齐全，但每行单独处理，且用了 `words = words + words` |
| docdist2 | 164.7 | 把上面的拼接改成 `+=` |
| docdist3 | 123.1 | 点积改用归并式，但排序还是 [[term:insertion-sort]] |
| docdist4 | 71.7 | 计数改用字典，但仍然要排序才能用归并式点积 |
| docdist5 | 18.3 | 拆词改用 `string.translate` |
| docdist6 | 11.5 | 排序换成 [[term:merge-sort]] |
| docdist7 | 1.8 | 计数完全用字典，排序彻底去掉 |
| docdist8 | 0.2 | 整篇处理，不再逐行 |

从 228 秒到 0.2 秒，一千多倍。要说清的是「什么没换、什么换了」：**三步的骨架一次都没换**（还是拆词、计数、点积），**但每一步内部用的算法与数据结构换了好几次**。表里每一步买到的倍数并不一样，可以按改动性质分成两类：

- 只动写法与常数因子：把拼接换成 `+=`（228.1 → 164.7，1.4 倍）、把拆词换成 `string.translate`（71.7 → 18.3，3.9 倍）、把逐行处理换成整篇（1.8 → 0.2，9 倍）；
- 换了算法或数据结构：把点积改成归并式（123.1 → 71.7，1.7 倍）、计数改用字典（71.7 → 18.3 里的一部分）、把插入排序换成归并排序（18.3 → 11.5，1.6 倍）、把排序整个换成字典（11.5 → 1.8，6.4 倍）。

这两类各买到多少倍，画在下面。

![每一步买到的倍数：只动写法的三步最多 9 倍，换算法或数据结构的一步 6.4 倍](figures/docdist-multipliers.svg)

按这些数说话，结论有两条：**最大的一跳（9 倍）来自「别逐行处理」这个写法上的决定**，而**第二大的（6.4 倍）来自把排序整个去掉**；两类都值得改，而哪一类更值，取决于你现在卡在哪一步。讲义只给了数字，这两句是我们按它那张表算的。

![八个版本的耗时：从 228 秒一路降到 0.2 秒，每一步买到了什么](figures/docdist-timings.svg)

这张表按对数刻度画，所以比的是量级而不是像素：从最上面一行到最下面一行跨度一千多倍，中间每一次变短都对应一次具体的改动。

## 读完应该能回答

- 计算模型规定了哪两件事，为什么这两件事必须先定下来；
- RAM 的三条 Θ(1) 操作分别是什么，字长为什么必须不小于 lg(内存大小)；
- 指针机比 RAM 弱在哪里，既然更弱，为什么这一讲还要留着它；
- Python 的 `L[i] = L[j] + 5` 与 `x = x.next` 各自对应哪个模型、各自为什么是 Θ(1)；
- 点积当文档距离为什么不满足尺度无关，归一化与反余弦各补上了什么；
- 拆词、计数、点积三步里，哪一步给出的是期望代价而不是最坏代价，为什么。

## 脉络回顾

这一讲给的不是某个算法，而是一把尺子。往后每一讲算代价时用的都是它：先问「这一步用到了 RAM 的哪条操作」，再问「Python 把它实现成几步」。第一讲里的峰值查找之所以能说「一轮只花 Θ(1)」，依据就来自这里；而第五讲、第六讲算递推式时出现的那两个 Θ(1)，同样是这里定下的价。

要分清的是，这一讲的文档距离本身只走到「定义清楚 + 代价分析」为止：三步各是什么、每步贵在哪，讲清楚了；至于字典为什么只是「高概率」快、表倍增怎么把 append 摊成 Θ(1)，那是第三单元（哈希）与第九讲的事。下一讲从排序开始，代价第一次变成可以比较的东西。
