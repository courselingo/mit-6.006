第 13 讲的 BFS 求的是最短路径，但它有一个前提：每条边都算一步。真实的路不是这样的，有的路段长、有的路段短，还有收费的。这一讲把「短」这件事重新定义，第一次让边带上权重。

讲义自己的标题是「Shortest Paths I: Intro」，它的 Lecture Overview 按顺序列了四件事：带权图、通用做法、负权边、最优子结构。前两件是这一讲的主体，后两件是它的边界与地基。讲义也点明了参考读物：教材 CLRS 的第 24 章开头。

## 一、这一讲要解决什么：带权图上的最短路

讲义用一句日常的话交代动机：

> 原文：Shortest way to drive from A to B Google maps "get directions"

然后把问题写成标准形式：

> 原文：Problem on a weighted graph G(V, E) W : E → ℝ. Two algorithms: Dijkstra O(V lg V + E) assumes non-negative edge weights; Bellman Ford O(V E) is a general algorithm

三件事一次说清了：所谓[[term:graph]]里的[[term:weighted-graph]]，就是每条边带一个实数[[term:weight]]；解决它的两个算法是 Dijkstra 与 Bellman-Ford；而它们的代价与前提不同，前者快但要求权重非负，后者慢一些却是一般算法。这一讲不展开这两个算法，只把问题与地基铺好。讲义要解的正是 [[term:shortest-path]] 问题。

讲义举的应用是从加州理工开车到麻省理工。建图的方式是：[[term:vertex]]是路口，[[term:edge]]是道路，而且是有向边（单行道），权重是距离或者过路费。路径的定义是顶点的一个序列 \(p = \langle v_0, v_1, \dots, v_k \rangle\)，要求相邻两个顶点之间都有边；而一条路径的权重就是它所有边的权重之和 \(w(p) = \sum_{i=0}^{k-1} w(v_i, v_{i+1})\)。

![带权图：顶点是路口，边是有向道路，权重是距离或过路费](figures/sssp-weighted-graph.svg)

把「最短路」变成一个可以计算的问题，靠的就是这个定义：路径的代价是它边上权重之和，而不是边的条数。

## 二、最短路径的定义与两个数据结构

讲义先补了一个简写：\(v_0 \xrightarrow{p} v_k\) 表示 \(p\) 是从 \(v_0\) 到 \(v_k\) 的一条路径；单独一个顶点 \((v_0)\) 也算一条路径，它的权重是 0。然后给出正式定义：

> 原文：Shortest path weight from u to v as δ(u, v) = min{w(p) : u → v} if ∃ any such path; ∞ otherwise (v unreachable from u)

也就是说，\(\delta(u, v)\) 是所有从 \(u\) 到 \(v\) 的路径里最小的那个权重；如果根本走不到，就记作无穷大。有了它，单源最短路径问题就一句话：

> 原文：Given G = (V, E), w and a source vertex S, find δ(S, V) [and the best path] from S to each v ∈ V

给定图、权重和一个源点，求它到**每一个**顶点的最短距离，并且把路径本身也找出来。注意这里要的是「单源」：一个起点，所有终点。

为了做这件事，讲义准备了两样东西：一个记录距离的数组 \(d\)，一个记录来路的数组 \(\Pi\)。

- \(d[v]\) 在初始化时只有源点是 0，其余都是无穷大；结束时它应当等于 \(\delta(s, v)\)；
- 而在整个过程中始终有 \(d[v] \ge \delta(s, v)\)，也就是说它一直是真实距离的一个**上界**，找到更好的路径时它会变小；
- \(\Pi[v]\) 记录「到 \(v\) 的最佳路径上，\(v\) 的前一个顶点」，也就是它的[[term:predecessor]]，源点的 \(\Pi[s]\) 记作 NIL。

这两条性质就是后面所有最短路径算法的共同契约：算法做的每一件事，都只是让 \(d\) 从无穷大一步步降到真值。

![两个数据结构：距离数组从无穷大单调下降到真值，前驱数组记录最佳路径上的来路](figures/sssp-data-structures.svg)

图里那三条线要连起来读：初始值全是无穷大、过程中 \(d\) 只会变小、结束时它必须落在真值上。

## 三、负权边：为什么有的最短路会「没有定义」

权重可以是负数吗？讲义说在某些场景里是自然的，比如把概率取对数当权重，而它同时点出了两处麻烦：

> 原文：Natural in some applications (e.g., logarithms used for weights). Some algorithms disallow negative weight edges (e.g., Dijkstra). If you have negative weight edges, you might also have negative weight cycles ⇒ may make certain shortest paths undefined!

第一处是说 Dijkstra 这类算法不允许负权；第二处更要紧：有了负权边，就可能出现[[term:negative-cycle]]，也就是绕一圈回来总权重还是负的环。一旦有这种环，某些最短路就**不存在**了，因为你可以绕着它走任意多圈，让路径权重一路往下掉。

讲义给的例子是：环 \(B \to D \to C \to B\) 的权重是 \(-6 + 2 + 3 = -1 < 0\)，确实是负环。于是从源点到 \(C\)（以及 \(B\)、\(D\)、\(E\)）的最短路**没有定义**，可以绕着这个环走任意多次；而从源点到 \(A\) 的最短路是有定义的，权重是 2。

讲义还顺势给了算法的一条义务：

> 原文：If negative weight edges are present, s.p. algorithm should find negative weight cycles (e.g., Bellman Ford)

也就是说，在允许负权的场合，算法不但要求出距离，还应当把负环找出来；讲义点名 Bellman-Ford 就是这样的算法。

![负权环：绕一圈总权重是负的，于是绕得越多路径越短，距离失去意义](figures/sssp-negative-cycle.svg)

这张图说明了「负权」与「负环」是两件不同的事：单独有负权边没问题，一旦能绕成负环，最短距离就不再是一个数。

## 四、通用结构：初始化加松弛

这一讲的核心是给出一个通用骨架，它不指定具体算法，只规定「所有最短路算法都在做的事」。初始化部分很直接：

> 原文：Initialize: for v ∈ V : d[v] ← ∞; Π[v] ← NIL; d[S] ← 0

然后是主循环。它的动作叫[[term:relaxation]]，中文一般叫松弛：

> 原文：Main: repeat: select edge (u, v) [somehow]; if d[v] > d[u] + w(u, v): d[v] ← d[u] + w(u, v); π[v] ← u; until all edges have d[v] ≤ d[u] + w(u, v)

读法是：随便挑一条边 \((u, v)\)，看看「先走到 \(u\)，再走这条边」是不是比现在记录的 \(d[v]\) 更短；如果更短，就把 \(d[v]\) 更新成这个值，并把 \(v\) 的前驱记成 \(u\)。反复做，直到每一条边都满足 \(d[v] \le d[u] + w(u, v)\)，也就是没有任何一条边还能被松弛。

这段骨架里最关键的两个字是 `[somehow]`：**它没有规定按什么顺序选边**。而这个空着的位置，正是后面两个算法唯一的区别，也是第五节要算的账。用 Python 写出来，它只有十几行：一个初始化循环，加一个反复挑边并尝试松弛的循环。

![松弛：如果先到 u 再走这条边比现在记录的更短，就更新距离并把前驱记成 u](figures/sssp-relax.svg)

看懂这张图，后面两讲就只剩下一个问题：用什么顺序去挑边，才能保证不用挑太多次。

## 五、代价：通用的做法可能慢到指数级

讲义接着问了两件必须回答的事：

> 原文：Termination? (needs to be shown even without negative cycles). Could be exponential time with poor choice of edges.

第一件是终止性：即使保证没有负环，也得证明这个过程会停下来，这一点并不显然，因为松弛可能反复更新同一个 \(d[v]\)。第二件更刺眼：如果边选得不好，这个通用过程可能跑**指数时间**。

讲义用一个例子说明有多糟。它的图分层排列，从 \(v_0\)、\(v_1\) 出去的边权重是 4，从 \(v_2\)、\(v_3\) 出去的边权重是 2，从 \(v_4\)、\(v_5\) 出去的是 1；推广到 \(n\) 个顶点时，第一组权重取 \(2^{n/2}\)，第二组取 \(2^{n/2}-1\)，以此类推。如果按一种病态的顺序选边，每一次松弛只能把 \(d(v_{n-1})\) 的值减少 1，而要把它从上界降到真值需要减掉一个指数大的数，于是总时间是 \(O(2^{n/2})\)；讲义在图里也写了这个递推：

> 原文：T(0) = 0; T(n+2) = 3 + 2T(n); T(n) = θ(2^{n/2})

**同一套骨架、同一张图，只因为挑边的顺序不同，代价就从多项式掉到了指数。** 这就是为什么后面要专门设计「按什么顺序挑边」：Dijkstra 与 Bellman-Ford 的差别，本质上就是这个顺序的差别。

![病态的选边顺序：每次只能把 d(v) 降 1，而缺口是指数大的，于是总时间是指数](figures/sssp-exponential.svg)

这张图是为了说明一件事：通用骨架本身不给任何时间保证，保证来自选边策略。

## 六、最优子结构：子路径也是最短路径

接下来是这一讲的地基，它的名字叫[[term:optimal-substructure]]，它解释了为什么「松弛」这种做法在逻辑上站得住：

> 原文：Theorem: Subpaths of shortest paths are shortest paths. Let p = < v0, v1, … vk > be a shortest path. Let pij = < vi, vi+1, … vj >, 0 ≤ i ≤ j ≤ k. Then pij is a shortest path.

用中文说：如果整条路径是最短的，那么它中间任意一段**子路径**也一定是最短的。证明是反证法：把 \(p\) 拆成 \(p_{0,i}\)、\(p_{ij}\)、\(p_{jk}\) 三段，假设中间那段 \(p_{ij}\) 不是最短的，那就存在一条更短的替代路径 \(p'_{ij}\)；把它替换进去，整条路径就比 \(p\) 更短了，这与 \(p\) 是最短路径矛盾。

这个定理的实际含义是：**最短路径可以由更小的最短路径拼出来**。所以算法不必一次看全整条路，只要在每一步保证「到某个顶点的这一段已经最短」即可，而松弛正是在做这件事。

![最优子结构：如果子路径不是最短的，换掉它就能得到比原路径更短的路，矛盾](figures/sssp-optimal-substructure.svg)

这张图是反证法的画面版：假定中间那段有更短的替代品，整条路径就不再最短。

## 七、三角不等式

讲义最后给了一条关于距离函数的性质，也就是[[term:triangle-inequality]]，它和上面的定理是同一件事的另一种说法：

> 原文：Theorem: For all u, v, x, we have δ(u, v) ≤ δ(u, x) + δ(x, v)

意思是：从 \(u\) 到 \(v\) 的最短距离，不会超过「先从 \(u\) 到 \(x\)、再从 \(x\) 到 \(v\)」这两段之和。因为后者本身就是一条从 \(u\) 到 \(v\) 的合法路径（经过 \(x\)），而 \(\delta(u, v)\) 是所有合法路径里最小的那个。

这条性质在算法里的用处很直接：**它是松弛条件的来源**。松弛时检查的 \(d[v] > d[u] + w(u, v)\)，就是想把「绕一下」与「直达」比较出更小的那个。

![三角不等式：经过 x 绕一下的距离之和，不会小于 u 到 v 的直接最短距离](figures/sssp-triangle.svg)

把这张图和上一张放在一起看：一个说「子路径必须最短」，一个说「绕路不会更短」，它们合起来支撑了松弛这一步的正当性。

## 读完应该能回答

- 带权图上的「最短路径」定义与无权图的差别在哪里，路径的权重怎么算；
- \(d[v]\) 与 \(\Pi[v]\) 各自记什么，为什么 \(d[v]\) 在过程中始终不小于真值；
- 负权边本身有没有问题，什么情况下最短距离会变成「没有定义」；
- 通用骨架里哪个位置留了空，为什么那个空会让代价从多项式变成指数。

## 脉络回顾

这一讲给第 13 讲的 BFS 补上了缺失的那一半。BFS 之所以能求最短路，靠的是「每条边都算一步」这个隐含前提，于是它按层展开时第一次到达就是最短；而一旦边有权重，「走了几步」就不再等于「走了多远」，按层展开也就失去了意义。求解的办法换成了另一种：维护每个顶点的当前最佳距离 \(d\)，用边不断去修正它。

要分清的是，**这一讲没有给出任何具体算法**，它给的是所有最短路径算法共用的三样东西：距离与前驱这两个数据结构、松弛这个动作、以及最优子结构与三角不等式这两条地基。而第五节用一张病态的例子说明，光有骨架不够，**挑边的顺序决定了代价**。下一讲的 Dijkstra 与再往后的 Bellman-Ford，就是给这个空位填上两种不同的顺序。
